# Deploying Cellar to Render

One Render **web service** runs the API and serves the built web app from the same address (required by the sign-in spec), plus one Render **PostgreSQL** database. Both are in Frankfurt. Everything is described in [`render.yaml`](render.yaml).

You'll do the account and secret steps yourself; nothing here needs a password typed into a chat.

---

## Before a public launch (from the specs)

- [ ] **Fill in `apps/web/src/legal/operator.ts`** — your name, contact email, country and data-protection authority. Until then the Terms and Privacy pages show a "draft" warning.
- [ ] **Have the Privacy notice and Terms reviewed** (`apps/web/src/legal/LegalPages.tsx`). They describe what the app really stores, but they are a starting point, not legal advice.
- [ ] **Account deletion** is not built (sign-in decision D3). The privacy notice says deletion requests are handled by email within 30 days — be ready to do that by hand.
- [ ] **Grape list licence** (add-wine OQ-4): the seeded grapes are a hand-made list, so nothing to check until VIVC data is imported.

---

## 1. Put the code on GitHub

Render deploys from a Git repository. Git isn't installed on this computer yet.

1. Install Git: https://git-scm.com/download/win (or run `winget install Git.Git`).
2. Create an **empty private** repository on https://github.com/new (no README), e.g. `cellar`.
3. In the project folder:

```bash
git init -b main
```

```bash
git add .
```

```bash
git commit -m "Cellar: sign-in, add wine, collection, view/edit wine"
```

```bash
git remote add origin https://github.com/YOUR-USER/cellar.git
```

```bash
git push -u origin main
```

`.env`, `.data/` (your local database) and `node_modules/` are in `.gitignore` and won't be uploaded.

## 2. Create the services on Render

1. Sign up at https://render.com and connect your GitHub account.
2. **New → Blueprint**, pick the `cellar` repository. Render reads `render.yaml` and proposes:
   - web service `cellar`
   - database `cellar-db`
3. **Choose paid plans for a public launch.** On the free plans the web service sleeps when idle (slow first load) and the free database is **deleted after 30 days** — your users' collections would be lost. The smallest paid web service and database plans are enough to start.
4. Render asks for the two values marked "sync: false": leave `GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET` **empty for now** if you don't have them yet (step 3), then **Apply**.
5. When the service is created, note its address, e.g. `https://cellar-xyz.onrender.com`. The first deploy will fail until the Google values are set — that's expected: the server refuses to start in production without real Google sign-in.

`SESSION_SECRET` is generated by Render, `DATABASE_URL` is wired to the database, and the app's public address is read from Render automatically (`RENDER_EXTERNAL_URL`).

## 3. Create the Google sign-in client

In https://console.cloud.google.com:

1. **Create a project**, e.g. "Cellar".
2. **APIs & Services → OAuth consent screen** (Google Auth Platform):
   - User type: **External**.
   - App name: **Cellar**; support email: yours.
   - App home page: `https://cellar-xyz.onrender.com`
   - Privacy policy: `https://cellar-xyz.onrender.com/privacy`
   - Terms of service: `https://cellar-xyz.onrender.com/terms`
   - Scopes: only **openid**, **…/auth/userinfo.email**, **…/auth/userinfo.profile** (all non-sensitive).
   - **Publish app** (status "In production"), so anyone can sign in, not only test users.
3. **Credentials → Create credentials → OAuth client ID**:
   - Type: **Web application**, name "Cellar production".
   - Authorized redirect URI: `https://cellar-xyz.onrender.com/api/v1/auth/google/callback`
   - No `localhost` URIs here — use a separate client for local development (sign-in spec §11).
4. Copy the **Client ID** and **Client secret** straight into Render: **cellar → Environment → GOOGLE_CLIENT_ID / GOOGLE_CLIENT_SECRET → Save changes**. Render redeploys.

> Google may ask to verify the app's branding (name, logo, domain) before showing it to everyone. With only basic scopes and no logo this is usually not required, but domain verification can't be done for an `onrender.com` address. If Google insists, add your own domain (step 5).

## 4. Check it

1. Open `https://cellar-xyz.onrender.com/api/v1/health` → `{"status":"ok"}`.
2. Open the address, **Sign in with Google**, tick the terms box, add a wine, open it, edit it.
3. Render dashboard → **Logs**: no errors; no codes, tokens or emails appear in the logs (sign-in §10).

Database migrations and seed data run automatically each time the service starts.

## 5. Later

- **Own domain:** Render → cellar → Settings → Custom Domains, add the DNS record it shows, then update the Google consent screen and redirect URI to the new address.
- **Backups:** paid Render databases keep daily backups; check the retention for your plan.
- **Updating the app:** commit and `git push` — Render redeploys automatically.
- **Changing the legal text:** bump `LEGAL_VERSION` in `operator.ts` and `TERMS_VERSION` in `render.yaml` together (re-accepting changed terms is sign-in OQ-3, not built yet).
